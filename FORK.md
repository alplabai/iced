## Upstream sync 2026-11-21 (signex-v0.15.0-alpha.9)

Merges upstream iced-rs/iced `master` at `98bd48fe0` (102 commits past `8ff48c42b`) and follows upstream fully, including the switch from tiny_skia to vello_cpu (maintainer decision, after Signex was tried against it on a trial branch).

What the merge brings:

- [#3306](https://github.com/iced-rs/iced/pull/3306): `vello_cpu` replaces `tiny_skia` as the software renderer. The `tiny_skia` crate and `iced_tiny_skia` are deleted; the `tiny-skia` feature is renamed `vello-cpu` (plus `vello-cpu-multithreading`); the headless backend name is `vello_cpu` (`vello-cpu`, `vello_cpu` or `software` select it), so snapshots are `*-vello_cpu.sha256`.
- [#3544](https://github.com/iced-rs/iced/pull/3544): `popover` widget and `overlay::Position` (with `Position::Auto { preference }` as the default). `tooltip(content, tip)` loses its `position` argument (use `.position(..)`) and its `padding`/`style`/`class` (style the tip itself); `Tooltip<W, V>` has no lifetime or theme parameter. `opaque` moves to its own module and returns `Opaque<W>`. `examples/tooltip` is folded into `tour`.
- Smaller upstream fixes: e5c350f27 (text selection while scrolling), a46f0a93b (`Rectangle::snap` for negative coordinates), c3d2cfd0a (frame clock rounds up), bbd4c2601 (`Component` overlay layout invalidation), 8836286bc (`scrollable` translation takes `Size`), b2fbd3cb6 (`Daemon::font` now sets the default `Font`; `Daemon::fonts` loads font bytes), edb068eeb (bounded `debug` messages), 797c8cbcf (real screen damage to softbuffer). The root `iced` dev-dependency no longer enables `advanced`.

Behaviour change: `opaque` now follows upstream. It captures mouse presses only; wheel scrolling passes through unless `.capture_scroll(true)` is set (fork #97 captured the wheel always). The fork's tests moved to `widget/tests/opaque_stack.rs` and opt in with `capture_scroll(true)`; upstream's `widget/tests/opaque.rs` is unchanged. Signex modals must add `.capture_scroll(true)`.

Fork deltas inside `vello_cpu` (each with a test):

- #123 fork rule: vello_cpu renders on several threads by default. `vello_cpu/Cargo.toml` turns on `vello_cpu/multithreading` for every target except `wasm32` (no threads there), so it uses `available_parallelism() - 1` threads, at most 8; upstream renders on one thread unless the app enables `vello-cpu-multithreading`. That feature stays and is now a no-op outside wasm; do not enable it on wasm32, where vello_cpu's `available_parallelism().unwrap()` panics. Test: `tests/multithreading.rs`, run by Fork CI on default features because `--all-features` would mask a revert.
- `src/text.rs` passes the font system version to the text cache (fork #3352/#3484).
- `tests/canvas_text_alignment.rs` (fork #100, ported from tiny_skia, `[[test]]` with `required-features = ["geometry"]`) passes all 6 cases.
- #3215: a failed image load (and a 0x0 image) stays cached as an error; upstream's vello_cpu stored `None` and panicked with "Image should be allocated" on the next lookup.
- #3542 fork rule: an SVG color mask scales the pixel coverage by the mask alpha, as on wgpu (upstream's vello_cpu ignored the mask alpha).
- #3434: `vector.rs` honours `Svg::current_color`, as tiny_skia did: the color goes to usvg as a style sheet (alpha 0 to 1) and the tree and raster caches are keyed on it, so two current colors never share an entry. The #3542 mask still applies after rasterizing. Tests: `current_color_fills_svg`, `current_color_keeps_its_alpha`.
- #3486: changed text damages 1 px more, like quads.
- #121: a text group or cache whose transformation or clip bounds changed damages its old and new positions, even when the texts inside are equal; upstream (and tiny_skia) compared only the texts and mapped both through the old transformation, so moved canvas text (a scrolled or panned layer) stayed at its old position on the software path. Tests: `moved_text_cache_damages_old_and_new_positions`, `moved_text_group_damages_old_and_new_positions`.
- #3531: a frame drawn at another scale factor is not used for damage.
- Layers are clipped to the viewport, so a renderer drawn without `reset()` (headless screenshots, test helpers) is not clipped away by its unbounded root layer.
- #3360 / canvas text clip: `Text::Cached` (canvas `fill_text`) intersects its clip with the layer bounds scaled to physical pixels; upstream multiplied the screen-space layer bounds by the item transformation, so canvas text in a layer away from the origin (scrollable, pane, clipped container) drew nothing. Test: `canvas_text_in_a_translated_layer_is_drawn`.
- #3412/#3445: `Text::Raw` intersects `Raw::clip_bounds` with the text and layer bounds, and a dropped buffer skips only that text (upstream returned from `draw`, leaving a clip pushed and skipping every later layer). Tests ported from tiny_skia.
- `impl graphics::text::Renderer` (`fill_raw`), which upstream's vello_cpu dropped and tiny_skia had: the fallback renderer needs it from both backends.
- #3391: per-side border widths and colours (`src/border_sides.rs`), same semantics as the old tiny_skia code: a border with no side overrides keeps the uniform stroke; zero-width sides paint nothing; rounded corners keep asymmetric widths (elliptical inner corners). Tests ported from tiny_skia.
- #40: `impl DrawPrimitive<P> for Frame` as a no-op, so `canvas::Frame::draw_primitive` compiles with wgpu + vello-cpu (the fallback `Frame` needs both backends to implement it). Test: `primitives_are_skipped`.
- #18: `Geometry` is a list of `Section`s (graphics `section::Kind`), as on tiny_skia and wgpu: shapes, images and text keep call order, and primitives are grouped by the clip of the frame that drew them, so `Frame::with_clip` clips shapes (before, child clips were dropped entirely). Primitives are now drawn with the group's transformation instead of a translation by the clip origin, which changes three things on vello_cpu: shapes of a canvas partly clipped by its layer (a scrollable or pane scrolled past the canvas top or left) were offset by the clipped amount and are now in place; shapes and stroke widths follow a scaled layer transformation; a root frame with a non-zero origin (`Frame::with_bounds`) no longer shifts its shapes, as on wgpu and tiny_skia. Tests: `a_wide_rounded_uniform_border_reaches_the_outer_curve`, `a_tight_corner_with_a_wide_border_is_masked_by_the_outer_curve`.

- Upstream #3501 (wgpu dashed strokes): `dashed` walks the flattened path itself instead of lyon's `walk_along_path`. No dash runs from one subpath into the next, dashes follow corners, a dash cut short by the end of the path is drawn, and on a closed subpath the last dash joins the first through the start point (also when it ends exactly there). Behaviour changes: the pattern restarts at each subpath (as in SVG and the tiny-skia backend) instead of continuing from the previous one; a pattern with no positive length strokes solid instead of drawing nothing; zero-length dashes (`[0, n]`) now reach the tessellator as zero-length subpaths. `offset` keeps its meaning (an index into `segments`, that interval drawn first); tiny-skia still reads it as a distance, and still strokes odd-length or negative patterns solid where wgpu repeats or clamps them. A walk that stops advancing in f32 ends early and draws the rest of that segment as the current interval, so dashing always ends. Tests in `wgpu/src/geometry.rs`.
- Upstream #3512 (wgpu image order): the image pipeline keeps images in submission order.
