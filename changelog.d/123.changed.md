- **Breaking: vello_cpu renders on several threads by default (#123)** — outside `wasm32`, the software renderer now always enables vello_cpu's `multithreading` and draws on `available_parallelism() - 1` threads (at most 8) instead of one; the `vello-cpu-multithreading` feature stays and changes nothing there. Signex: the vello_cpu fallback (`ICED_BACKEND=vello-cpu`, headless tests) uses several cores with no Signex change; an explicit `vello-cpu-multithreading` opt-in is no longer needed (and is harmless).
